# aionas-savings changelog

Each release is the git tag `aionas-savings-vX.Y.Z`. With auto-update on, Claude Code picks a release up from the marketplace; it applies from the next session.

## 0.7.0 (2026-11-20)

- **Savings per request are recorded again in Claude Desktop** (AIO‑1099): Claude Desktop's Code tab gives the plugin's hooks no prompt id, so 0.6.1 dropped every per-request record there (sub-agents moved to Sonnet, handoffs). The plugin now takes the prompt id from the session's own transcript (that one id field only, never the prompt, the reply or tool output), for the sub-agent records and for the handoff. A prompt that arrives without an id no longer erases the one the plugin already knew. Terminal sessions work as before. Nothing new leaves the computer: the record is the same session id, prompt id, method and time as in 0.6.1.
- **A warning before your 5-hour Claude window or Fable's weekly cap runs out** (AIO‑1083): from 80% the band shows one warning row with the percentage and the reset time, and sub-agents run on Sonnet until the window resets. At 90% you get one toast per window suggesting `/model sonnet`. The plugin never switches your main model: that stays your choice. The effort grant (xhigh, max) is held while the warning is on. A reading that is stale, from a past window, from the future or malformed is ignored (no warning, no count). It reads local files only, runs only when the gateway lists the `limit_guard` capability, and counts `fired`, `skipped`, `window_reached` and `window_reset` under the method `limit_guard`. New: `lib/limit-guard.sh`. **Needs gateway v0.33.0.**
- **The plugin knows whether it runs in Cursor and runs only what fits Cursor** (AIO‑1077): hooks that need Claude Code's mod, band or settings stay out of Cursor; counts and per-turn records from Cursor are kept apart and tagged `client` = `cursor`, sent only when the gateway's policy lists `counters_client` / `requests_client` (an older gateway gets exactly the 0.6.1 bodies for Claude Code, and Cursor rows wait). The 15-second stall at the end of a turn is gone.
- **A handoff offer in Cursor** (AIO‑1079): on the stop that crosses the handoff threshold, Cursor gets one offer to continue in a new conversation.
- **The Cursor reporter script updates itself too** (AIO‑1076): the script refresh now also covers `aionas-cursor-hooks-reporter.sh` and `.ps1` (when already installed), and lists the new sha256 of the plan collector and the status-line taps (they carry a release stamp and the window figures the guard reads). Same checks as before: listed sha256 only, atomic replace, `.prev` kept a day.
- **Reports each session's git branch, for Work Items** (AIO‑1019): a new `UserPromptSubmit` hook, `branch-report.sh`, runs in the background and never delays the prompt. It reads only `session_id` and `cwd` from the hook input, asks git for the branch and commit of that folder, and sends `{session_id, branch, head_sha, observed_at}` plus the repository's bare name (worked out on the computer from the origin remote; the URL, which can carry a user or a token, never leaves) to `POST /enroll/v1/cc-session-git` with the enrollment alias, once per change per session (a failed send is retried on the next prompt). The prompt and the folder path are never read, kept or sent. Outside a repository, on a detached HEAD, without git or on a computer that is not enrolled, nothing is sent. Egress manifest: one new route.
- **The admin sees which commit and which PR each session made, and in which app** (AIO‑1088): a new hook, `git-event.sh`, runs after a Bash command (Claude Code) or a shell command (Cursor) that succeeded as a `git commit`, a `gh pr create` or a `git push`, in the background and without delaying anything. It sends only the session id, the event kind (commit, pr or push), the branch, the commit sha, the PR number, the repository's bare name, the app (`client`: `claude_code` or `cursor`) and the time. Never the command, its arguments, the commit message, the diff or the output. It sends only when the gateway's policy lists `session_git_events`; an older gateway receives nothing new. Nothing is sent for a command that failed, or outside a repository or on a computer that is not enrolled.
- **What leaves the computer:** one new optional field `client` (`cursor`) on counter rows and per-turn records, and the new counter names `window_reset` and `window_reached` under `limit_guard`. New on `POST /enroll/v1/cc-session-git` (branch report and git events): `event` (commit, pr or push), `pr_number` (an integer, for a PR only) and `client` (`claude_code` or `cursor`), next to the session id, branch, commit sha, repository bare name and time. Numbers and names only; nothing else.

## 0.6.1 (2026-11-19)

- **Second review round (AIO‑1072):** the settings rewrite's temporary file is created exclusively with `mktemp` (a planted file or link at a predictable name can no longer be written through), and the usage probe follows a `claude` symlink chain to its end (at most 40 hops) and refuses it if any folder on the way is inside the workspace.

- **This is the release of the changes below.** The tag `aionas-savings-v0.6.0` was created by mistake on the 0.5.0 code before this work was merged, and release tags cannot be moved or deleted, so 0.6.0 was never released with this content; it is the same as 0.5.0. Nothing changed in the code since the changes were written as 0.6.0.

- **Security fixes from the second-model review** (AIO‑1072; the issues are in 0.5.0 code too): every HTTP call starts with `--disable` (the developer's `.curlrc` is never read), allows only the gateway's scheme (`https`, or `http` for the loopback gateway), follows no redirect, and succeeds only on exit status 0 and a 2xx. The state folder `~/.aionas/agent/savings` must be the user's own, mode 0700 and not a symlink (group or other read bits are dropped; a folder others can write to makes the plugin write and send nothing); the auth header file is a fresh `mktemp` file. The script refresh installs a script only when its sha256, with the release line set back to the placeholder, is listed in `security/script-allowlist.txt`, shipped inside the plugin (the four scripts gateways v0.28.0 to v0.31.2 serve); anything else is refused and counted locally (`counters/script_refresh_refused`, never sent). The usage probe never runs `claude` from `PATH` or from inside the workspace (only `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, Claude Desktop, the VS Code extension) and starts it through `/usr/bin/env -i` with a short list of variables. The Windows handoff launcher writes `%` as `%%`, and none is written for a path with a double quote. The daily scan runs no `nice` or `nohup` from `PATH`, and `security/egress-manifest.txt` lists the scanner's own upload (`delegated`) and the one program the hook starts (`run`). The unused-services hook writes Claude's settings only if they are unchanged since it read them, and replaces a symlinked file at its target instead of truncating it. The handoff Stop hook decodes the JSON of `transcript_path` and `cwd` (a Windows path or a quote no longer stops the timer). Both READMEs and `SECURITY.md` now list, field by field, what the plan report and the usage probe send, including the organization id and name and the full `/usage` text.
- **Every method that acts is now reported per prompt, so applied savings can be checked request by request** (AIO‑1004): until now nothing in the plugin called `POST /enroll/v1/savings/requests`, so the server had daily totals but no record to tie them to. At the end of each turn (the existing Stop hook, `counters-flush.sh`) the plugin sends one record per method that acted on that turn (`subagent_sonnet`, `output_trim`, `handoff`): `session_id`, `prompt_id`, `method`, `ts`, `plugin_version`, and `tokens` where the plugin measured it (the output left out of the context for `output_trim`, the context size at the handoff). Nothing else: no prompt text, file path, command, tool output or cost (the gateway prices it). Marks wait in `~/.aionas/agent/savings/requests/` until the turn's prompt id is known; a record that cannot be sent waits for the next turn (at most 5 minutes between failed tries, two days, 200 records), one the server refuses is dropped and counted. New: `lib/requests.sh`, and the endpoint in `security/egress-manifest.txt`.
- **Tool output trimming is removed from the plugin** (AIO‑1073; Tal's ruling 18.11: it is no longer offered). Gone: the `output_trim` method (its PreToolUse and PostToolUse hooks `noisy-guard.sh` / `output-store.sh`, `posttool-store.*`, `pretool-guard.*`, `rules/guard-store.tsv`), the `aionas-recall` command, its band chip and its `/aionas-bypass` names (`trim`, `guard`, `store`, `noisy_guard`, `output_store`). A policy row for it from the gateway is ignored; the gateway keeps mirroring it for older plugins. Outputs an earlier version stored under `~/.aionas/agent/savings/store/` are no longer read or pruned.
- **A per-request record names the prompt it belongs to when the method acts, never a later one** (AIO‑1073): sub-agent marks used to wait per session and go to whatever turn's Stop ran next, so an interrupted turn's marks went to the next turn and a late Stop could take a later turn's. A new UserPromptSubmit hook (`request-prompt.sh`) keeps Claude Code's `prompt_id` for the session (the id Claude Code sets for each prompt before that hook runs, and carries on every later hook, the Stop's included); a mark takes that id when it is made; with none, the mark is dropped. The Stop no longer assigns anything.
- **`subagent_sonnet` counts and reports only a sub-agent the policy actually moved** (AIO‑1073): the mod counted every sub-agent start while the method was on, before the start. Now it counts after the start, and only an agent that named no model, is no fork and whose parent is not on Sonnet: fired and one record when it started on the policy's Sonnet, skipped when the method was off for it; an agent with its own model, or already on Sonnet, counts nothing.
- **Records and counters are no longer lost, sent twice or counted twice when hooks overlap or are stopped** (AIO‑1073): each mark and each counter increment is a spool file of its own, written whole and renamed into place, so an append can no longer race a flush. The counter totals and the names of the spool files they include are written in one rename, and the inputs removed only after it, so a flush stopped in between never counts them again and a failed write keeps everything. A spool file of records is removed only once every record in it was accepted or refused, so a stopped flush leaves the rest for the next one (the gateway keeps one record per prompt and method, so a resend changes nothing). One deadline now covers the whole Stop flush: no send starts more than 3 s after the hook started, so records, the policy refresh and the counters together stay inside its 10 s. What an earlier build queued (`queue.tsv`, `.batch.*`, `.left.*`, `batch.*`, `pending.tsv`) is taken over once.
- **The band's /compact runs once per press and shows that it is compacting** (AIO‑1022): the button had no guard and no state, so each press added another `/compact` to Claude Code's queue (Tamar's transcript shows four). Now at most one `/compact` is in flight per session (terminal and desktop): presses meanwhile do nothing and the button is a dim "Compacting…" label. It returns if the command fails, if the context size is still above `compact_at` 10 seconds after it ran, or after 2 minutes without any new size.
- **Daily counters are sent as the computer's running total, not as increments** (AIO‑1004): the gateway stores a counter's value as this computer's total for the UTC day and replaces it on each send, so a day with more than one hourly send used to keep only the last increment. The plugin now keeps the day's total per method and counter in its existing counters folder (hooks still only append; the hourly flush folds them in under the existing lock, so several Claude sessions on one computer add up), sends the total, and prunes past days once the send is confirmed. An unchanged total is not sent again. The same fields as before; nothing new leaves the computer. Works with any gateway version; gateway v0.31.0 also never lowers a stored day value, so a resend is harmless. If the plugin's local state is lost (a reinstall), that day's new counts show only once they pass what the gateway already holds for the day.
- **After /compact or the handoff the band says what it did** (AIO‑1023): one line from the band's own context readings before and after, once per action ("Compacted: 209K → 26K tokens, about 183K fewer tokens on each next turn"; after "Continue in a new conversation" in the terminal "New conversation: 209K → 12K tokens, …"; in the desktop app, where the new conversation is a session of its own, "Continued in a new conversation: it starts without this chat's 209K tokens."). It is not part of "saved since install" and shows no dollar figure; "No saving measured yet" is not drawn once an action line is shown. Each press of the band's /compact adds one `compact_pressed` count under the `handoff` method to the hourly counters send, in a request of its own (a gateway that does not know the name yet refuses only that count, never the day's other counters); a `/compact` the member types is never counted. **Needs gateway v0.31.0** to be stored.

## 0.5.0 (2026-11-01)

- **The band and the mod's scripts find Git Bash on Windows** (AIO‑905): inside Claude Desktop the mod ran its scripts with the bare word `bash`, which on Windows is missing or is the WSL launcher, so the band never showed. It now uses `CLAUDE_CODE_GIT_BASH_PATH` when that names a file, else `Program Files\Git\bin\bash.exe`, `Program Files (x86)\Git\bin\bash.exe` or the per-user `Programs\Git\bin\bash.exe`, never `PATH` and never Windows' own `bash.exe`. Existence is checked by starting the candidate with `-c true`, so the mod reads no file. Where none starts the band shows one plain line and the session says so; the path found is kept in `~/.aionas/agent/state/git-bash-path`. macOS and Linux are unchanged.
- **Plan detection reads the member's own tier, knows Ultra, and names the Claude organization** (AIO‑899, AIO‑900, AIO‑901): the plan report uses `userRateLimitTier` (else the organization's) so a Team premium seat is `team_premium`; a tier containing `ultra` is `max_20x` (plan ids are unchanged); every sample also carries `organization_uuid` and a cleaned `organization_name` when Claude Code has them.
- **The installed plan collector and status-line tap refresh themselves** (AIO‑904): once a UTC day, at session start, an enrolled computer asks the gateway for the current release of `aionas-plan-usage` and `aionas-statusline-tap` (`.sh` and `.ps1`) and, for a script that is already installed and differs, downloads it from the gateway's public route without sending the enrollment alias. It installs only after the sha256 matches (hash tool at a fixed system path, never `PATH`), a `.sh` starts with `#!`, and the copy is renamed over the old one atomically; the old copy stays one day as `<name>.prev`. Any failed check keeps the old script and tries again the next day. `settings.json` is never written.
- **Weekly plan usage for members who run Claude Code outside the terminal** (AIO-892): Claude Desktop and the VS Code extension never render the status line, so the status-line tap sent them no weekly figure. At session start, at most once every 4 hours per computer, on an enrolled computer signed in with a Claude subscription and only when the status-line tap stored no weekly figure in the last 4 hours (terminal users without the tap included), the plugin runs Claude Code's own `claude -p "/usage" --no-session-persistence --output-format json` (a local command: no model call; `claude` on `PATH`, else the newest Claude Desktop bundle, else the VS Code extension's) and sends the whole text of its result, unparsed, as one `usage_cmd` sample (`usage_raw`, at most 32 KiB; an error result or a larger one is not sent) to the organization's own gateway, which reads the weekly figure out of it. The text includes Claude Code's own "What's contributing" section (local folder names, skill, sub-agent, MCP and plugin names, request counts); prompts and replies never leave. The child runs with `AIONAS_USAGE_PROBE=1`, and every plugin hook ends at once when it sees that variable. The login token is never read.
- **Counts when "Sonnet for sub-agents" acts and when it does not** (AIO‑898): on each sub-agent start the mod's existing `agent.spawn` handler runs `aionas-bypass.sh --subagent-start`, which adds one `subagent_sonnet` `fired` count while the method is active for the session, else one `skipped`. Nothing else changes: no new hook, no new call (the hourly counters send carries the rows), nothing counted on a computer that is not enrolled or inside the usage probe's child, and the Sonnet choice itself is untouched.

## 0.4.1 (2026-11-01)

**Without the one install, the plugin does nothing.** The repository is public, so anyone can install the plugin by hand. On a computer the one install never enrolled (no alias in `~/.aionas/agent/credential`), every method is off, required ones too: no session context, sub-agents keep the person's own model, no handoff, no output trim, and the band draws nothing. Nothing was sent from such a computer before either; now nothing changes on it. An enrolled computer is unchanged: with no policy cached yet, every method is on as before.

## 0.4.0 (2026-10-29)

**Security hardening: this plugin runs on customer computers and updates itself from a public repository.**

- The daily scan runs the scanner only from where the installer puts it (`$AIONAS_SCAN_BIN`, `~/.aionas/agent/tools`, `~/.aionas/agent/bin`), never from `PATH`: a project or package could put its own `aionas-scan` there and have it run detached.
- The gateway address in the enrollment file must be `https://`; plain `http://` is accepted only for `localhost` and `127.0.0.1`.
- The `npm install` rule no longer adds `--no-audit`, so npm's vulnerability audit is never switched off.
- Band names drop C1 control and bidirectional-override characters, so a name from the policy cannot reorder or hide what the band shows.
- `security/egress-manifest.txt` lists every file, hook, network call and gateway endpoint the plugin uses; CI fails when the code and the list disagree.
- The marketplace sets `forceRemoveDeletedPlugins`, so taking the plugin out of the catalog removes it from every computer.

## 0.3.1 (2026-10-28)

**Turning off "Sonnet for sub-agents" now brings sub-agents back to the person's own setting (AIO-884).**

- Before: the one install wrote `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` into `~/.claude/settings.json`, and the plugin never read the method's state. Turned off with the band's chip, `/aionas-bypass subagent_sonnet` or the organization's policy, sub-agents still ran on Sonnet.
- Now: the plugin sets the variable inside the running session, just before each sub-agent starts, and takes it off again while the method is off, released or bypassed. Its bypass and its end apply from the next sub-agent of a running session; the organization's policy applies from the next session, as for every method.
- The person's own value (in `settings.json`, the shell or a project's settings) is kept whatever the method's state. The Sonnet an older install wrote is recognized by the install's own marker and is taken off too, so members on an older install are fixed by this update alone.
- `settings.json` is never written by the plugin.
- New: `aionas-bypass.sh --subagent-model BASE` (the decision), the mod's `agent.spawn` hook, and `AIONAS_SUBAGENT_MODEL` in `lib/catalog.sh`.
- Proof: real Claude Code 2.1.311 against a local mock of the Messages API, two sub-agents per session (lab `probes/subagent-sonnet-off/midsession`, `run-plugin.sh`). On, then bypassed between them: Sonnet then the default. Install-written Sonnet, then bypassed: Sonnet then the default. The person's own opus: opus both times. Bypassed, then ended: the default then Sonnet. Off by the organization: the default both times. 0.2.0 on the same case: Sonnet both times.
- To follow, in the gateway repo (AIO-885): the one install stops writing the variable and takes back the value an older install wrote. That ships after this release.
